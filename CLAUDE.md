# Uptime by GenLayer

Uptime: a paid GEN cron for GenLayer — schedule any call/deploy/read and track
results. **Bradbury Heartbeat** is ONE example job: a correctness-over-time
benchmark for the **Bradbury** testnet (five test types every hour, graded
ON-CHAIN, served as JSON for its dashboard and for Grafana). "Heartbeat" names
only that example job, its contract and its code — never the product.
Overview, probe table and setup: `README.md`. External surface: `INTEGRATIONS.md`.

## Invariants

- **Prompts and the answer key are frozen, on-chain.** `PROBES` and
  `ANSWER_KEY` in `contracts/src/heartbeat.py` are the benchmark; the contract
  grades every answer itself (`correct | wrong | injected`) and the runner only
  copies the grade. Never grade off-chain, and never put the key in a prompt.
  The key is public on purpose (this repo is public). Changing a prompt, a key
  or a fixture means a NEW deployment and a new results history.
- **`frontend/src/lib/heartbeat/probes.ts` mirrors the contract's probe ids,
  types and equivalences, in rotation order** — no answers in it.
  `test/direct` fails on drift.
- **Fixtures are frozen too.** `frontend/public/heartbeat/*` is fetched by the
  contract and served `immutable` (`next.config.ts`). HTML fixtures carry a
  sentinel `HB2-<id>`; `card.png` is pinned by `CARD_SHA256`. `card.png` and
  `shot.html` come from `frontend/scripts/heartbeat-fixtures.mjs` (`--check`
  must stay green; never commit regenerated bytes that differ).
- `frontend/src/lib/heartbeat/canary.ts` is GENERATED by `contracts/build.py` (both
  builds of `contracts/src/canary.py`; a job deploys the one for its network) —
  Vercel's root is `frontend/`.
- The tick never waits on consensus (60s function limit). Submit in `tick`,
  measure in `reconcile`, using chain timestamps.
- Cron routes fail closed without `CRON_SECRET`.
- Pushing `main` deploys to Vercel production.
- **One source, one build per network GenVM** (owner, 2026-11-06: keep the contracts
  running on BOTH Bradbury and Studio through every GenVM change). Edit only
  `contracts/src/<name>.py` (newest SDK, v0.6); `contracts/build.py` writes
  `contracts/build/{bradbury,studio}/<name>.py` from `contracts/targets.json` (runner
  pin + SDK rewrites per target). Generated files are committed: never hand-edit them,
  and `python3 contracts/build.py --check` must pass. Deploy only from `build/<target>/`.
  Bradbury/studio-next = `py-genlayer:babwp9t…` (GenVM v0.6.0-rc10); Studio =
  `py-genlayer:1jb45aa8…` (GenVM v0.2.16). A wrong pin fails every deploy with
  `invalid_contract runner malformed`. Before any deploy run `contracts/verify.sh --network`
  (Studio `gen_getContractSchemaForCode`, Bradbury `gen_call` deploy: no transaction).
  GenVM bump runbook: `contracts/README.md`.

### Jobs backend

- **`frontend/src/lib/jobs/types.ts` is a shared contract** (backend, jobs UI,
  shell). Change it only by agreement.
- **Gates are server-side and run twice**: at create/edit/resume
  (`lib/jobs/service.ts`) AND before every run (`lib/jobs/gate.ts` from the
  executor). Never gate only in the UI.
- **Wallet lists live in env, never in the repo**: `STUDIO_ALLOWLIST` (Labs +
  Foundation wallets allowed on Studio) and `UPTIME_ADMIN_WALLETS` (operators:
  view all jobs, pause any). Comma-separated, normalized, read at call time;
  unset or empty = nobody (fail closed). Everyone else runs on Bradbury and pays
  from their own pool.
- **Pool ids are first-come on-chain**: always compare the pool's on-chain
  owner with the job owner before running or charging.
- **Pool charging stays OFF** (`POOL_CHARGING_ENABLED`) until the pool is
  deployed and reviewed. A sent charge with an unknown outcome is never retried.
- Migrations are append-only `frontend/migrations/NNN_*.sql`, applied by
  `npm run db:migrate`. 001 is the jobs schema, 010 the mailer's, 011 the Heartbeat's results, 012 the self-serve alert settings,
  013 lets the Heartbeat record `write` probes (KV is only a fallback without `DATABASE_URL` or before
  011 + 013; see README "Store").

## Verify

```bash
contracts/verify.sh --network            # build drift + direct tests + genvm-lint per target + live load checks
# (= python3 contracts/build.py --check; UPTIME_TARGET=<t> pytest test/direct; genvm-lint per target;
#  venvs: .venv = genlayer-test 0.30.0rc2 for v0.6, .venv-studio = 0.29.2 for v0.2 — contracts/README.md)
(cd frontend && node scripts/heartbeat-fixtures.mjs --check)
(cd contracts/evm && forge test)
cd frontend && npx tsc --noEmit && npx eslint src && npx vitest run && npx next build
# SQL suite too: TEST_DATABASE_URL=postgres://localhost/uptime_test npx vitest run
```

## Layout

```
contracts/src/                  THE contract sources (heartbeat, canary, web_probe, ask, mail_escrow)
contracts/build/<target>/       generated per-GenVM builds (bradbury, studio); deploy from here
contracts/targets.json          runner pin, SDK rewrites, RPC and checks per target (README.md there)
contracts/src/heartbeat.py      probes, frozen prompts + on-chain answer key and grading
contracts/src/canary.py         deployed fresh each tick (inlined per network in lib/heartbeat/canary.ts, generated)
contracts/src/mail_escrow.py    email credit escrow, fee released on DKIM evidence (MAIL_ESCROW.md)
frontend/public/heartbeat/      fixtures the contract fetches
frontend/src/lib/heartbeat/     runner (tick/reconcile), store (Postgres; KV fallback), probe catalogue, summary
frontend/src/app/api/cron/      heartbeat (hourly, legacy) + dispatch (5 min) + reconcile (10 min) + settle (hourly)
frontend/src/app/api/heartbeat  public JSON (summary, or ?format=rows for Grafana)
frontend/src/lib/jobs/          jobs backend: types (shared), spec, schedule/cron, repo (pg),
                                executor, gate, service, auth (SIWE), pool, presets, export
frontend/src/lib/pool/abi.ts    UptimePool ABI (client-safe)
frontend/src/app/api/{auth,me,jobs,presets}  jobs API
frontend/migrations/            SQL migrations; scripts/migrate.mjs applies them
frontend/test/                  vitest (unit + optional Postgres suite)
test/direct/                    direct-mode contract tests
```

UI: Uptime is a separate app with its OWN design — GenLayer-inspired but lightly
branded, NOT the GenLayer Design System (no `gl-*` classes, no design-system CSS).
Tokens in `frontend/src/app/globals.css`; build pages from
`frontend/src/components/ui/` and the shell in `components/shell/` (the
not-audited banner is on every page by the root layout). This repo is PUBLIC:
never commit F37 Lineca here.
